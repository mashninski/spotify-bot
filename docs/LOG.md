# LOG.md — журнал змен

> Храналагічны журнал: новыя запісы **дадаюцца ўнізе**. Для старту сесіі хопіць апошніх ~40 радкоў.
> Пішам адразу пасля лагічнага кроку. Сакрэты ў журнал не запісваем.

## Формат запісу

```
### ГГГГ-ММ-ДД · тып · кароткі загаловак
- Што: ...
- Дзе: файлы / branch / хэш commit
- Праверка: што і як праверана (або «не правяралася»)
```

Тыпы: `зроблена`, `зменена`, `праверана`, `выдалена`, `перапрацавана`.

Для `выдалена` і `перапрацавана` абавязкова дадаць:

```
- Прычына: ...
- Замена: ...
- Як аднавіць: хэш commit / тэг, каманда, напрыклад `git show <hash>:шлях/да/файла`
```

### 2026-10-10 · праверана (часткова) · Рызыкі ADR-009
- Па зыходным кодзе obs-browser (`obs-browser-plugin.cpp`, `panel/browser-panel.cpp`, `panel/browser-panel-client.cpp`, галіна `master`):
  - пераход старонкі дока на іншы адрас **дазволены** (`OnBeforeBrowse` блакуе толькі спецыяльныя «forced popups») — значыць, уваход у Spotify/Twitch праз перанакіраванне ўсёй старонкі дока павінен працаваць;
  - `window.open` / `target=_blank` з дока **адкрываюцца ў сістэмным браўзеры** (`OnBeforePopup`, `OnOpenURLFromTab` → `QDesktopServices::openUrl`) — popup-уваход не падыходзіць;
  - у дока **асобнае сховішча** (`CefRequestContext` з уласным `cache_path`) — `localStorage` дока, хутчэй за ўсё, не бачны оверлею;
  - vendor-запыт `obs-browser` / `emit_event` існуе і дастаўляе падзеі ў Browser Source.
- У звычайным браўзеры: перанакіраванне праз `https://httpbin.org/redirect-to` → `callback.html` → док працуе, `localStorage` захоўваецца.
- Схаваны док: у звычайным браўзеры перыяды «схаваны» запісваюцца; паводзіны ў OBS (ці запавольваюцца таймеры, ці перазагружаецца док) — правярае аўтар (кнопкі і запісы на ўкладцы «Праверка»).
