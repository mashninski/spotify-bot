# PROJECT.md — памяць праекта

> Актуальны стан праекта. Абнаўляецца пры змене стану. Гісторыя — у `LOG.md`, рашэнні — у `DECISIONS.md`, ідэі — у `BACKLOG.md`.

**Апошняе абнаўленне:** 2026-10-10 · **Этап:** 3а (Spotify) правераны ў OBS; паляпшэнні хуткасці і гучнасць

## Мэта

Лёгкае модульнае прыкладанне для стрымераў на **Twitch** з **OBS**: паказвае на экране, што зараз грае ў **Spotify**, і дазваляе гледачам заказваць песні за **баллы канала**. Прыкладанне распаўсюджваецца сярод іншых стрымераў: просты ўсталёўка, усе падключэнні (Spotify, Twitch) — праз налады ўнутры прыкладання. У будучыні — іншыя крыніцы музыкі (напрыклад, YouTube-плэер) у межах аднаго бота. Код пішацца з нуля.

## Функцыі (узгоднена з аўтарам 2026-10-10)

### MVP
1. **Оверлей** (OBS Browser Source): кампактная палоска ў колерах Spotify з лагатыпам — назва і выканаўца бягучай песні, **візуалізацыя, якая рэагуе на гук** (waveline). Пад ёй драбнейшым шрыфтам — 3 наступныя песні (без слова «далей», але візуальна зразумела, што гэта чарга); каля заказанай песні — дробна нік гледача. Стрымер свабодна размяшчае і рухае оверлей у кожнай сцэне OBS.
2. **Док-панэль** (OBS Custom Browser Dock): што грае зараз; «паўза», «наступная», «папярэдняя»; спіс чаргі; каля кожнай песні — «выдаліць» (крыжык) і «прайграць зараз» (адразу пераключае, астатняя чарга захоўвае парадак); каля бягучай песні — **«+»: дадаць у «Любімыя трэкі» Spotify стрымера** (каб захаваць класную песню ад гледача; калі ўжо дададзена — паказваецца адзнака; узгоднена з аўтарам 2026-10-10); налады.
3. **Сінхранізацыя са Spotify**: калі стрымер пераключае музыку ў самім Spotify, оверлей і док гэта бачаць. Музыку стрымер запускае ў Spotify сам (любы плэйліст); калі заказаў няма — паказваюцца наступныя трэкі з яго кантэксту.
4. **Заказ песні за баллы канала**: узнагароду «Заказаць песню» стварае само прыкладанне. Глядач піша спасылку на трэк або назву. Правілы (мяняюцца ў наладах): цана **1000**; песня **не даўжэй за 12 хвілін**; **не больш за 2** песні аднаго гледача ў чарзе адначасова; песню, якая ўжо ў чарзе, нельга заказаць паўторна; explicit **дазволены** (можна забараніць у наладах). Калі песня не знойдзена або парушае правілы — **баллы вяртаюцца аўтаматычна**.
5. **Паведамленні ў чат ад імя стрымера** (без асобнага бота): «дададзена, №N у чарзе», «не знайшоў, баллы вернуты» і г. д.
6. **Налады ўнутры дока**: «Падключыць Spotify», «Падключыць Twitch», пароль obs-websocket, выбар аўдыякрыніцы для візуалізацыі, правілы заказаў.
7. **Нічога не запускаецца асобна**: усё працуе ўнутры OBS і стартуе разам з ім (ADR-009).
8. Мова гледачоў і інтэрфейсу — **беларуская**; платформа — **Windows** (ADR-010).

### Потым (не MVP)
- Кіраванне плэйлістамі з дока (выбар, з чаго граць).
- YouTube-плэер як другая крыніца музыкі.
- Поўны спектр гуку (патрабуе роднага C++-плагіна, гл. BACKLOG B-003).

## Стэк і архітэктура

Статычнае вэб-прыкладанне на **TypeScript** (зборка **Vite**, UI — **Preact**, тэсты — **Vitest**), якое выконваецца ўбудаваным браўзерам OBS. «Мозг» (чарга, заказы, падключэнне да OBS) працуе ў адной са старонак — у доку або ў оверлеі; яна выбіраецца праз Web Locks, астатнія паказваюць стан і шлюць каманды праз `BroadcastChannel` (ADR-015, `src/brain/`). Узровень гуку — праз **obs-websocket**. Ніякіх асобных працэсаў. Spotify — Web API з браўзера, уваход PKCE, токены ў `localStorage`, апытанне робіць лідар (ADR-016, `src/providers/spotify/`). Падрабязна: `DECISIONS.md`, ADR-007…016. Канал «мозг» → оверлей — obs-browser `emit_event` праз obs-websocket і `BroadcastChannel` (ADR-013). Node.js патрэбны толькі для распрацоўкі і зборкі.

## Актуальны стан

- Дакументацыя і правілы працы створаны (`CLAUDE.md`, `docs/`), Claude самастойны ў распрацоўцы (ADR-005).
- Git: галіна `main`, `origin` → `https://github.com/mashninski/spotify-bot.git` (прыватны). `.env` і `docs/CONTEXT.md` ігнаруюцца (праверана).
- Этап 1 скончаны: функцыі MVP узгоднены, архітэктура выбрана (ADR-007…011).
- Этап 2 **скончаны і правераны ў OBS аўтарам**: док і оверлей на тэставых даных, кнопкі дока мяняюць оверлей, waveline рэагуе на гук (obs-websocket 5.7.4, канал `emit_event`), інтэрфейс па ADR-014. 43 тэсты праходзяць.
- Этап 2.1 **скончаны і правераны аўтарам у OBS** (ADR-015, `src/brain/`): OBS з закрытым докам — бот працуе ў оверлеі, хваля рухаецца; кнопкі дока кіруюць ботам у оверлеі; закрыццё дока, перазагрузка оверлея-лідара і перазапуск OBS не губляюць чаргу; другі бот не з’яўляўся. 63 тэсты праходзяць.
- Этап 3а **зроблены, не правераны з сапраўдным Spotify** (галіна `feature/spotify`, ADR-016): уваход у Spotify з дока (PKCE), «зараз грае» і чарга Spotify ў доку і оверлеі, кнопкі дока кіруюць Spotify, «+» у «Любімыя трэкі», апытанне робіць лідар (працуе і пры закрытым доку). Без Spotify бот нічога не грае. 115 тэстаў праходзяць; у браўзеры праверана з падробкай Spotify. Чакаем праверку аўтара (`SETUP.md`).
- Рызыкі ADR-009 правераны: перанакіраванне ў доку працуе; закрыты док працягвае працаваць; **док, закрыты пры запуску OBS, не загружаецца** → патрэбен ADR-015; `localStorage` і `BroadcastChannel` агульныя для дока і оверлея.
- Асяроддзе аўтара: Windows 11, OBS 32.2.2, Node.js 24.19.0, npm 11.17.0. obs-websocket у OBS трэба ўключыць (крокі ў `SETUP.md`). Spotify Premium — ёсць. Twitch Developer — ёсць (для гэтага праекта ствараем новае Application тыпу *Public*, ADR-004).

## Наступная задача

**1. Аўтар правярае Этап 3а ў OBS** (`SETUP.md`: «Падключэнне Spotify», «Праверка Этапу 3а»). Пакуль ідзе праверка, файлы не мяняць. Па выніках — выправіць памылкі, зліць `feature/spotify` у `main`, удакладніць інтэрвалы апытання па «Запытаў да Spotify сёння» (ADR-016).

**2. Этап 3б (новая сесія Claude Code):** уласная чарга заказаў → Spotify (ADR-007).
- Пошук трэка ў Spotify па спасылцы або назве (`GET /search`, `limit` да 10; спасылка `open.spotify.com/track/…` → `GET /tracks/{id}`), праверка правілаў (`core/rules.ts`).
- Заказ трапляе ў Spotify (`POST /me/player/queue`) незадоўга да канца бягучай песні; «прайграць зараз» — у чаргу Spotify + «наступная»; «выдаліць» — толькі з нашай чаргі. Улічыць, што чарга Spotify (`GET /me/player/queue`) пасля гэтага змесціць заказ — не паказваць яго двойчы.
- «+ Тэставы заказ» пры падключаным Spotify — сапраўдныя трэкі праз пошук.
- Тэсты, крокі праверкі ў OBS.

**Крытэрыі гатоўнасці 3б:** тэставы заказ з дока знаходзіцца ў Spotify, стаіць у чарзе дока і оверлея з нікам гледача, грае пасля бягучай песні; «выдаліць» і «прайграць зараз» працуюць; правілы заказаў выконваюцца; тэсты праходзяць; праверана аўтарам.

## Каманды запуску і праверкі

Патрабуецца Node.js 24+ (толькі для распрацоўкі). Усе каманды — у папцы праекта.

| Каманда | Што робіць |
|---|---|
| `npm install` | Усталяваць залежнасці (першы раз і пасля змены `package.json`) |
| `npm run dev` | Dev-сервер на `http://127.0.0.1:5173/` (толькі лакальна) |
| `npm test` | Тэсты Vitest (адзін прагон) |
| `npm run test:watch` | Тэсты ў рэжыме назірання |
| `npm run typecheck` | Праверка тыпаў TypeScript |
| `npm run build` | Праверка тыпаў + зборка ў `dist/` |
| `npm run preview` | Паказ зборкі на `http://127.0.0.1:4173/` |

Старонкі (пры `npm run dev`):
- `http://127.0.0.1:5173/dock.html` — док (OBS → Док-панели → Пользовательские док-панели браузера);
- `http://127.0.0.1:5173/overlay.html` — оверлей (Browser Source 520×170); `?debug=1` — дыягностыка, `?demo=1` — тэставыя даныя без дока;
- `http://127.0.0.1:5173/` — спіс спасылак.

Праверка без OBS: адкрыць док і оверлей у дзвюх укладках аднаго браўзера — сувязь ідзе праз `BroadcastChannel`; у наладах дока «Крыніца гуку → імітацыя».
