# PROJECT.md — памяць праекта

> Актуальны стан праекта. Абнаўляецца пры змене стану. Гісторыя — у `LOG.md`, рашэнні — у `DECISIONS.md`, ідэі — у `BACKLOG.md`.

**Апошняе абнаўленне:** 2026-10-10 · **Этап:** 1 — вызначэнне функцый і стэка

## Мэта

Лёгкае модульнае прыкладанне для стрымераў на **Twitch** з **OBS**: паказвае на экране, што зараз грае ў **Spotify**, і дазваляе гледачам заказваць песні за **баллы канала**. Прыкладанне распаўсюджваецца сярод іншых стрымераў: просты ўсталёўка, усе падключэнні (Spotify, Twitch) — праз налады ўнутры прыкладання. У будучыні — іншыя крыніцы музыкі (напрыклад, YouTube-плэер) у межах аднаго бота. Код пішацца з нуля.

## Функцыі (чарнавік па апісанні аўтара 2026-10-10)

### MVP
1. **Оверлей** (OBS Browser Source): кампактная палоска ў колерах Spotify з лагатыпам — назва і выканаўца бягучай песні, ненавязлівая анімацыя «музыка грае» (waveline). Пад ёй драбнейшым шрыфтам — 3 наступныя песні (без слова «далей», але візуальна зразумела, што гэта чарга). Стрымер свабодна размяшчае і рухае оверлей у кожнай сцэне OBS.
2. **Док-панэль** (OBS Custom Browser Dock): што грае зараз; кнопкі «паўза», «наступная», «папярэдняя»; спіс чаргі; каля кожнай песні — «выдаліць» (крыжык) і «прайграць зараз». «Прайграць зараз» адразу пераключае песню, астатняя чарга захоўвае парадак.
3. **Сінхранізацыя са Spotify**: калі стрымер пераключае музыку ў самім Spotify, оверлей і док гэта бачаць.
4. **Заказ песні за баллы канала**: глядач актывуе ўзнагароду (1000 баллаў), піша спасылку на трэк або назву; песня трапляе ў чаргу. Заказы гледачоў ідуць першымі; калі заказаў няма — паказваюцца наступныя трэкі з таго, што стрымер запусціў у Spotify (плэйліст, «Любімыя трэкі» і г. д.).
5. **Налады ўнутры прыкладання**: кнопкі «Падключыць Spotify» і «Падключыць Twitch» для асабістых акаўнтаў стрымера.

### Потым (не MVP)
- Кіраванне плэйлістамі з дока (выбар, з чаго граць).
- YouTube-плэер як другая крыніца музыкі.

## Стэк і архітэктура

Чарнавое рашэнне — `DECISIONS.md`, ADR-006…008: лакальнае прыкладанне на кампутары стрымера (TypeScript / Node.js), якое аддае оверлей і док як вэб-старонкі для OBS; уласная чарга заказаў; кожны стрымер падключае свой Spotify праз уласны Client ID; Twitch — праз Device Code Flow і ўзнагароду, створаную самім прыкладаннем.

## Адкрытыя пытанні (трэба ўдакладніць у аўтара)

1. Twitch Application: прапанова — новае Application тыпу *Public* (ADR-004, ADR-008). Чакае рашэння аўтара; патрэбна толькі перад падключэннем Twitch.
2. Мова тэкстаў для гледачоў (оверлей, адказы ў чаце) і мова інтэрфейсу дока/налад для іншых стрымераў.
3. Платформа: толькі Windows ці таксама macOS?
4. Правілы заказаў: ліміты (даўжыня песні, колькі заказаў на аднаго гледача, паўторы, explicit), вяртанне баллаў пры памылцы.
5. Ці павінен бот адказваць у чаце («Песня дададзена, №3 у чарзе»)?
6. Ці паказваць на оверлеі нік гледача, які заказаў песню?
7. Анімацыя «музыка грае»: дэкаратыўная (Spotify не аддае гук) — ці дастаткова?
8. Ці ёсць у аўтара Spotify Premium (без яго кіраванне прайграваннем праз API немагчыма)?
