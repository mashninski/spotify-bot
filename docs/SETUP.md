# SETUP.md — што трэба зрабіць аўтару

> Толькі неабходнае. Рэгістрацыі, якія патрэбны пазней, пазначаны як «адкладзена» — рабіць іх зараз не трэба.
> Назвы пунктаў меню OBS дадзены па-руску і па-англійску (як у інтэрфейсе OBS).

## Падключэнне прыкладання да OBS (распрацоўка; праверана на Этапе 2)

### 1. Запусціць прыкладанне
1. Тэрмінал у папцы `D:\production\spotify-bot`.
2. Першы раз: `npm install`.
3. `npm run dev` — з'явіцца `Local: http://127.0.0.1:5173/`. Тэрмінал **не зачыняць**, пакуль ідзе праверка (Ctrl+C — спыніць).
4. **Калі тэрмінал — PowerShell** і паказвае памылку «выполнение сценариев отключено в этой системе» (`npm.ps1`): пісаць `npm.cmd` замест `npm` (`npm.cmd install`, `npm.cmd run dev`) або адкрыць тэрмінал `cmd` (у Правадніку ў адрасным радку папкі набраць `cmd` і Enter) — там працуе звычайны `npm`. Мяняць палітыку бяспекі Windows для праекта не трэба.

### 2. Уключыць obs-websocket
1. OBS → **Сервис → Настройки сервера WebSocket** (*Tools → WebSocket Server Settings*).
2. Галачка **Включить сервер WebSocket** (*Enable WebSocket server*). Порт пакінуць `4455`. **Включить аутентификацию** (*Enable Authentication*) — пакінуць уключанай.
3. **Показать сведения о подключении** (*Show Connect Info*) → скапіяваць пароль. Пароль нікому не паказваць і ў чат не ўстаўляць.
4. **ОК**.

### 3. Дадаць док
1. OBS → **Док-панели → Пользовательские док-панели браузера…** (*Docks → Custom Browser Docks…*).
2. Назва: `Spotify-бот`, URL: `http://127.0.0.1:5173/dock.html` → **Применить** (*Apply*). Док з'явіцца — яго можна перацягнуць куды зручна.
3. У доку: укладка **Налады** → уставіць пароль obs-websocket → **Падключыцца**. Кропка справа ўверсе павінна стаць зялёнай, ніжэй — «Канал да оверлея: obs-browser (emit_event)…».

### 4. Дадаць оверлей
1. У сцэне: **Источники → + → Браузер** (*Sources → + → Browser*), назва `Spotify оверлей`.
2. URL: `http://127.0.0.1:5173/overlay.html`, шырыня `520`, вышыня `170`. Астатняе — па змаўчанні → **ОК**.
3. Для праверак дадаць другую крыніцу «Браузер» з URL `http://127.0.0.1:5173/overlay.html?debug=1` (жоўты тэкст дыягностыкі). Пасля праверак яе можна выдаліць.

### 5. Што праверыць
1. **Кнопкі** у доку (Плэер): «наступная», «паўза», «прайграць зараз», «выдаліць», «+ Тэставы заказ» — оверлей адразу мяняецца. (З Этапу 3а без Spotify плэер пусты, а тэставы заказ адразу становіцца бягучай песняй; з падключаным Spotify кнопкі кіруюць Spotify.)
2. **Waveline**: Налады → «Крыніца гуку». Пасля падключэння там спіс крыніц OBS з палоскамі ўзроўню. Для першай праверкі — «Гук працоўнага стала» (*Desktop Audio*), уключыць любую музыку → хваля ў оверлеі рухаецца ў рытм. Лепшы варыянт на будучыню — асобная крыніца **Захват звука приложения** (*Application Audio Capture*) са Spotify; каб гук не задвоіўся ў стрыме, у **Расширенные свойства звука** (*Advanced Audio Properties*) у яе можна зняць усе дарожкі (*Tracks*) — [не праверана, што ўзровень пры гэтым працягвае паступаць].
3. **Оверлей з `?debug=1`** — паведаміць Claude, што напісана: «канал: …» (чакаецца `obs-browser`) і «localStorage дока бачны / НЕ бачны» (па кодзе OBS чакаецца «НЕ бачны»).
4. **Схаваны док**: закрыць док крыжыкам і пачакаць **6–7 хвілін**, гледзячы на debug-оверлей: «сігнал дока: N с таму» павінен заставацца ≈0–2 с, песні — мяняцца ў свой час, waveline — рухацца. Потым адкрыць док праз меню **Док-панели → Spotify-бот**, укладка **Праверка** → блок «Ці працуе схаваны док»: паведаміць Claude радкі (перыяд, «звычайны таймер», «worker-таймер», «падзей ад OBS», час загрузкі дока).
5. **Перанакіраванне**: Праверка → «Праверыць перанакіраванне» → праз 1–2 с док вяртаецца, і з'яўляецца зялёны тэкст «Працуе…». Калі док застаўся на старонцы httpbin.org або паказаў памылку — паведаміць Claude.
6. **Popup**: Праверка → «Адкрыць акно» — паведаміць, дзе адкрылася акно (чакаецца: у звычайным браўзеры).

Калі нешта не так — скрыншот дока (укладка «Праверка») і debug-оверлея дапамогуць.

## Праверка Этапу 2.1 у OBS: бот працуе без дока (ADR-015)

Патрэбна тое ж, што вышэй: `npm run dev` працуе, док, оверлей і debug-оверлей (`overlay.html?debug=1`) дададзены, obs-websocket падключаўся хоць раз, у наладах выбрана крыніца гуку. Пакуль ідзе праверка, Claude файлы не мяняе (кожная праўка перазагружае док і оверлеі).

1. **Запуск OBS з закрытым докам.** Закрыць док крыжыкам, выйсці з OBS (*Файл → Выход*), запусціць OBS зноў (док не адкрываць). Уключыць музыку.
   - Чакаецца: оверлей паказвае песню і 3 наступныя, хваля рухаецца ў рытм; праз 3–4 хвіліны песня мяняецца сама.
   - Debug-оверлей: «Бот працуе ў гэтым оверлеі» або «…ў іншым оверлеі», «Web Locks ёсць», «сігнал бота: 0–2 с таму». Радка «УВАГА: другі бот» быць не павінна.
2. **Адкрыць док** (*Док-панели → Spotify-бот*).
   - «Праверка» → «Дзе працуе бот»: «Бот працуе ў оверлеі з …», «Выбар старонкі для бота: Web Locks», без «Увага».
   - «Плэер»: «наступная», «паўза», «прайграць зараз», «выдаліць», «+ Тэставы заказ» — оверлей адразу мяняецца, у доку з’яўляецца паведамленне пра заказ.
   - «Налады»: кропка зялёная, у «Хваля ў оверлеі» — спіс крыніц з палоскамі.
3. **Закрыць і адкрыць док.** Чарга ў доку і ў оверлеі тая ж, бот застаецца ў оверлеі.
4. **Перазагрузіць оверлей, у якім працуе бот** (у debug-оверлеі напісана «у гэтым оверлеі» — значыць, ён): крыніца → *Свойства* → **Обновить кэш текущей страницы** (*Refresh cache of current page*) → *ОК*.
   - Чакаецца: праз 1–2 с бот працуе ў іншай старонцы (паглядзець у «Праверцы» дока), чарга не змянілася, песня працягваецца прыкладна з таго ж месца, хваля рухаецца.
5. **Перазапуск OBS з адкрытым докам.** Выйсці з OBS з адкрытым докам і запусціць зноў: усё загрузілася само, чарга тая ж, нідзе няма «Увага: заўважаны другі бот».

Вынікі: скрыншоты debug-оверлея і блока «Дзе працуе бот» пасля крокаў 1, 2 і 4; што не спрацавала — апісаць.

## Падключэнне Spotify (Этап 3а, ADR-016)

Патрэбны **Spotify Premium** (без яго Spotify не дае кіраваць плэерам праз API). Client ID — не сакрэт, але **Client Secret нікому не паказваць і нікуды не ўстаўляць**: ён нам не патрэбны.

### 1. Стварыць прыкладанне Spotify (адзін раз)
1. У звычайным браўзеры адкрыць `https://developer.spotify.com/dashboard` і ўвайсці сваім акаўнтам Spotify. Пры першым уваходзе Spotify можа папрасіць пацвердзіць пошту і пагадзіцца з умовамі для распрацоўшчыкаў.
2. **Create app**. Запоўніць:
   - **App name**: `Spotify-бот для OBS` (любая назва; яе ўбачыце на старонцы ўваходу).
   - **App description**: `Паказвае песню на стрыме і кіруе плэерам` (любы тэкст).
   - **Website** — можна пакінуць пустым.
   - **Redirect URIs**: `http://127.0.0.1:5173/callback.html` → **Add**. Менавіта так: `127.0.0.1`, не `localhost` (Spotify яго забараняе), без прабелаў і касой рысы ў канцы. Гэты ж адрас паказаны ў доку: «Налады» → «Spotify» → «Адрас вяртання» (кнопка «Капіяваць»).
   - **Which API/SDKs are you planning to use?** — адзначыць **Web API**.
   - Галачка згоды з умовамі (*I understand and agree…*) → **Save**.
3. Адкрыецца старонка прыкладання. **Client ID** — радок з 32 сімвалаў уверсе (на старонцы *Settings* / *Basic Information*). Скапіяваць яго. «View client secret» не націскаць — сакрэт не патрэбны.
4. Калі пазней Spotify адкажа «няма доступу» (док напіша пра «User Management»): на старонцы прыкладання → **Settings → User Management** → дадаць сябе (імя і email акаўнта Spotify) → **Add user**. Уладальнік прыкладання звычайна мае доступ і без гэтага [не праверана].

### 2. Падключыць Spotify у доку (у OBS)
1. `npm run dev` працуе, док адкрыты ў OBS.
2. Док → **Налады** → блок **Spotify** → уставіць Client ID у поле «Client ID». Пад полем не павінна быць чырвонага тэксту.
3. **Падключыць Spotify**. Док сам пяройдзе на старонку ўваходу Spotify. Калі яна дробная — пашырыць док або правая кнопка мышы па пустым месцы старонкі → **Zoom Out / Уменьшить** [назвы пунктаў па кодзе obs-browser, не праверана].
4. Увайсці праз **email** (паролем або кодам з пошты). Кнопкі «Увайсці праз Google / Facebook / Apple» у доку могуць не спрацаваць: акно ўваходу адкрыецца ў звычайным браўзеры (ADR-009).
5. Spotify пакажа, якія правы просіць прыкладанне → **Принять / Agree**. Док вернецца на «Налады», там будзе «Падключаны акаўнт …».
6. **Калі на старонцы Spotify з’явілася памылка** (напрыклад, `INVALID_CLIENT: Invalid redirect URI`): правая кнопка мышы па пустым месцы старонкі ў доку → **Назад** (*Back*) — док вернецца. Праверыць Redirect URI і Client ID у Spotify Dashboard. Калі «Назад» няма — OBS → **Док-панели → Пользовательские док-панели браузера…** → **Применить** (док загрузіцца нанова) [не праверана].

## Праверка Этапу 3а у OBS

Патрэбна: `npm run dev` працуе, док і оверлей дададзены (можна і debug-оверлей), Spotify падключаны (раздзел вышэй), музыка ўключана ў дадатку Spotify на гэтым жа камп’ютары. Пакуль ідзе праверка, Claude файлы не мяняе.

1. **Зараз грае.** Док «Плэер» і оверлей паказваюць тую ж песню, што ў Spotify; час песні ідзе; у «Далей у Spotify» і пад песняй у оверлеі — наступныя песні з чаргі/плэйліста Spotify.
2. **Пераключэнне ў самім Spotify.** У дадатку Spotify націснуць «наступная», потым паўзу, потым уключыць іншы плэйліст. Чакаецца: док і оверлей мяняюцца **не пазней чым праз 6 с** (на паўзе — да 15 с). Калі песня скончылася сама — новая з’яўляецца амаль адразу.
3. **Кнопкі дока.** «Наступная», «Папярэдняя», «Паўза/Працягнуць» — Spotify слухаецца, док і оверлей мяняюцца праз ~1 с. Калі Spotify нідзе не адкрыты — док піша «Spotify нідзе не адкрыты…».
4. **«+» каля назвы песні.** Націснуць → паведамленне «Дададзена ў «Любімыя трэкі»», «+» становіцца зялёнай галачкай; у Spotify песня ёсць у «Любимые треки». Песня, якая ўжо была ў «Любімых», адразу паказваецца з галачкай.
5. **Бот без дока.** Закрыць док крыжыкам і пераключыць песню ў Spotify — оверлей мяняецца. Яшчэ мацнейшая праверка: выйсці з OBS з **закрытым** докам, запусціць OBS, док не адкрываць — оверлей паказвае тое, што грае ў Spotify.
6. **Праверка → Spotify.** Паведаміць Claude лічбу «Запытаў да Spotify сёння» і прыкладна колькі гадзін за дзень працаваў OBS — па ёй удакладнім частату апытання (ADR-016).
7. **Адключыць / падключыць.** «Налады» → Spotify → «Адключыць» → у доку «Spotify не падключаны», оверлей пусты. Падключыць зноў — працуе без уводу Client ID.

Вынікі: што спрацавала, што не; скрыншоты дока («Плэер» і «Праверка») пры праблемах.

## Праверка паляпшэнняў Этапу 3а (хуткасць, гучнасць, анімацыя)

1. **Кнопкі дока:** «Наступная» / «Папярэдняя» — назва ў доку мяняецца адразу (без 2–6 с), Spotify пераключаецца, праз секунду нічога не скача назад.
2. **Хуткае выяўленне змен у Spotify:** у OBS павінна быць хоць адна крыніца **Захват звука приложения**, **Захват окна** або **Захват игры** — бот чытае з яе налад спіс акон (выбранае ў ёй акно не важна, крыніца можа быць схаванай). Асобная крыніца толькі дзеля гэтага не патрэбна. Захват звука самога Spotify патрэбны, толькі калі хочаце, каб хваля ў оверлеі рэагавала толькі на музыку, а не на ўвесь гук рабочага стала (тады не дубляваць гук на стрыме). Док → «Праверка» → Spotify: зялёны радок «Бот бачыць акно Spotify праз OBS…». Пераключыць песню або паставіць паўзу ў самім Spotify — док і оверлей мяняюцца прыкладна праз 1 с. Праверыць таксама са **згорнутым** Spotify і паведаміць, што піша «Праверка».
3. **Spotify закрыты → адкрыты:** з крыніцай з п. 2 — каля 1–2 с; без яе — да 15 с.
4. **Гучнасць:** паўзунок справа ад кнопак мяняе гучнасць у дадатку Spotify; значок дынаміка — «без гуку» і назад.
5. **Анімацыя:** змена песні ў оверлеі плаўная (старая назва сыходзіць уверх, новая з’яўляецца знізу).
6. Лічба «Запытаў да Spotify сёння» і колькі гадзін працаваў OBS.

## Праверка Этапу 3б у OBS: заказы гледачоў → Spotify (ADR-017)

Падрыхтоўка: OBS з докам і оверлеем, Spotify падключаны і грае плэйліст. Пра ўсе праверкі — скрыншоты або словамі, што бачыце.

1. **Анімацыя:** пераключыце песню — у оверлеі старая назва сыходзіць уверх, потым знізу з’яўляецца новая, без накладання і рыўкоў; радкі чаргі пад ёй плаўна пад’язджаюць.
2. **Заказ па спасылцы і па назве:** док → «Заказы гледачоў» → «+ Тэставы заказ» два разы. Першы — па спасылцы (Rick Astley — Never Gonna Give You Up), другі — па назве (NaviBand — Гісторыя майго жыцця). Абодва ў доку з нікамі гледачоў, у оверлеі — у чарзе з нікам. У самім Spotify у чарзе іх пакуль **няма** — так і трэба.
3. **Гульня пасля бягучай песні:** перамотайце бягучую песню ў Spotify амаль да канца (за ~30 с) і пачакайце. За ~15 с да канца першы заказ з’явіцца ў чарзе Spotify («Далей у чарзе»), у доку ён застаецца ў «Заказах» і **не** з’яўляецца другі раз у «Далей у Spotify». Пасля канца песні ён грае: у доку і оверлеі — назва з нікам, з «Заказаў» ён знікае.
4. **«Наступная»:** пры заказах у чарзе кнопка «Наступная» ў доку адразу ўключае першы заказ (не плэйліст).
5. **«Прайграць зараз» і «выдаліць»:** дадайце 3 тэставыя заказы. ✕ каля аднаго — ён знікае з дока і оверлея і не з’яўляецца ў Spotify. ▶ каля апошняга — ён адразу грае ў Spotify з нікам, астатнія заказы застаюцца ў тым жа парадку.
6. **Правілы:** у «Наладах» забараніце explicit або паменшыце даўжыню да 3 хв і дадайце тэставы заказ — над «Заказамі» з’явіцца прычына (напрыклад, «…даўжэй за 3 хв»), заказ у чаргу не трапіць. Сёмы тэставы заказ — «Rush — 2112» (20 хв) — адмова «даўжэй за 12 хв» і з правіламі па змаўчанні. Правіла «не больш за 2 ад гледача» — калі выпадковы нік паўтарыцца ў трэці раз. Пасля праверкі вярніце налады.
7. **Змена лідара:** калі заказ ужо ў чарзе Spotify (крок 3, апошнія 15 с), закрыйце док крыжыкам. Пасля канца песні заказ грае адзін раз з нікам у оверлеі; адкрыйце док — заказ не задвоіўся ні ў доку, ні ў Spotify.
8. **Spotify закрыты:** з заказам у чарзе закрыйце Spotify, адкрыйце і ўключыце музыку — заказ застаўся ў доку і зайграе пасля песні (адзін раз).
9. «Праверка» → лічба «Запытаў да Spotify сёння» ў канцы.

**Пераправерка пасля заўваг (рывок, перамотка, парадак):**
1. Націсніце «Наступная» ў доку — у оверлеі старая назва адразу пачынае сыходзіць, без мільгання новай.
2. Перамотайце песню ў Spotify у сярэдзіну — у доку час абновіцца не пазней чым праз 10 с (з заказамі ў чарзе — 5 с).
3. Дадайце 2 тэставыя заказы і перамотайце бягучую песню ў самы канец (апошнія 3–10 с). Пасля яе граюць абодва заказы запар; калі бот не паспеў, песня з плэйліста можа прагучаць каля секунды і пераключыцца на заказ.
4. Тое ж, але націсніце «наступная» ў самім Spotify — пачынае граць першы заказ.

## Хваля толькі па Spotify (без голасу і гукаў рабочага стала)

1. Крыніца **Захват звука приложения** → у наладах крыніцы «Окно» выберыце `[Spotify.exe]: …` (калі Spotify на паўзе, загаловак — «Spotify Premium»). Пры прайграванні ў «Мікшары» каля гэтай крыніцы павінна рухацца зялёная палоска.
2. Каб музыка не гучала на стрыме **двойчы** (яна ўжо ёсць у «Звук рабочего стола»): правы клік па мікшары → **Расширенные свойства звука** → у радку гэтай крыніцы зняць усе галачкі **Дорожки** (1–6), «Мониторинг звука» — «Выкл». Паўзунок гучнасці крыніцы пакінуць на 0 дБ і **не выключаць гук** значком дынаміка — інакш бот не ўбачыць узровень.
3. Док → «Налады» → «Хваля ў оверлеі» → «Крыніца гуку» — гэтая крыніца.
4. Ціхая фонавая музыка — хваля павінна выразна рухацца (праз некалькі секунд пасля пачатку песні яна падладжваецца пад гучнасць); на паўзе — спакойная лінія; ваш голас хвалю не рухае.

## Падключэнне Twitch (Этап 4, ADR-018)

Уваход — па кодзе (Device Code Flow): Client Secret **не патрэбны**, у Twitch нічога не трэба ствараць, акрамя прыкладання. Client ID — не сакрэт. Калі Twitch усё ж пакажа кнопку **New Secret** — не націскаць.

### 1. Зарэгістраваць Twitch Application (адзін раз)
1. Двухфактарная аўтэнтыфікацыя (Twitch патрабуе яе для рэгістрацыі прыкладанняў): `https://www.twitch.tv/settings/security` → **Безопасность и конфиденциальность → Двухфакторная аутентификация** (*Security → Two-Factor Authentication*). Калі ўжо ўключана — прапусціць.
2. У звычайным браўзеры адкрыць `https://dev.twitch.tv/console` → **Log in with Twitch** (акаўнт таго ж канала, дзе баллы). Калі консоль просіць пацвердзіць пошту — пацвердзіць і абнавіць старонку.
3. Укладка **Applications** → **Register Your Application**.
4. Запоўніць:
   - **Название** (*Name*) — унікальная на ўвесь Twitch, напрыклад `Spotify-bot OBS` + ваш нік. Калі назва занятая — дадаць лічбу. Слова «Twitch» у назве, магчыма, не дазволена [не праверана].
   - **OAuth Redirect URL** — `http://localhost` → **Добавить** (*Add*). Бот гэты адрас не выкарыстоўвае (уваход па кодзе), але поле абавязковае. Пустыя лішнія радкі выдаліць кнопкай **Удалить** — інакш Twitch піша «URL-адреса должны использовать протокол HTTPS» і кнопка «Создать» неактыўная. Калі Twitch не прымае `http://localhost` — `https://localhost`.
   - **Категория** — **Broadcaster Suite**.
   - **Тып кліента** (*Client Type*) — **«виден всем»** (так у рускім інтэрфейсе перакладзены *Public*). Не «Конфиденциально».
   - **I'm not a robot** (калі ёсць) → **Создать** (*Create*).
5. У спісе прыкладанняў → **Управление** (*Manage*) → скапіяваць **Client ID** (радок з ~30 сімвалаў).

### 2. Падключыць Twitch у доку (у OBS)
1. `npm run dev` працуе, OBS з докам і оверлеем, Spotify падключаны і грае (без Spotify узнагарода будзе на паўзе).
2. Док → **Налады** → блок **Twitch** → уставіць Client ID → **Падключыць Twitch**.
3. Док пакажа код з 8 літар і адкрые ў звычайным браўзеры старонку `twitch.tv/activate` (калі не адкрылася — кнопка «Адкрыць twitch.tv/activate»). Праверыць, што код на старонцы такі ж, як у доку → **Activate / Активировать** → на старонцы дазволаў **Authorize / Разрешить**.
4. Праз некалькі секунд у доку: «Падключаны канал …» і «Узнагарода «Замовіць песню» за 1000 баллаў працуе».
5. Калі док напісаў «Twitch не прыняў Client ID» — праверыць Client ID і тып **Public**; «Код састарэў» — націснуць «Падключыць Twitch» зноў (код дзейнічае 30 хв).

## Праверка Этапу 4 на канале (ADR-018)

Падрыхтоўка: OBS з докам і оверлеем, Spotify падключаны і грае плэйліст, Twitch падключаны. Замаўляць лепш **з другога акаўнта** (або папрасіць сябра): ці можна купіць сваю ж узнагароду з акаўнта стрымера, не праверана. На другім акаўнце павінна быць ≥ 1000 баллаў (або часова паменшыць кошт ў «Правілах замоў», напрыклад да 1). Пакуль ідзе праверка, Claude файлы не мяняе.

1. **Узнагарода.** На старонцы канала → **Баллы канала**: ёсць «Замовіць песню» з коштам з налад і падказкай пра спасылку або назву. Змяніць кошт у доку («Правілы замоў») — праз некалькі секунд кошт змяняецца і на Twitch.
2. **Замова па спасылцы.** Купіць узнагароду, уставіць спасылку на трэк Spotify (у Spotify: «Поделиться → Скопировать ссылку на трек»). Чакаецца за 1–3 с: у доку ў «Замовах гледачоў» — песня з нікам, у оверлеі — у чарзе з нікам, у чаце ад вашага імя — «Гурт — Назва стала ў чаргу». У панэлі аўтара Twitch (**Очередь запросов наград** / *Reward Requests Queue*) замова «чакае» — так і трэба.
3. **Замова па назве.** Напрыклад, «Queen Bohemian Rhapsody» — тое ж самае.
4. **Песня зайграла → «выканана».** Націснуць ▶ каля замовы ў доку (або дачакацца канца песні). Песня грае ў Spotify, оверлей — з нікам, у чарзе запытаў Twitch замова знікае (статус «выканана»). Баллы гледачу не вяртаюцца.
5. **Адмова — баллы вернуты.** Замовіць «ыыыы ъъъъ» — у чаце «не знайшоў «…» у Spotify, баллы вернуты», баллы гледача вярнуліся. Замовіць «Rush 2112» — «даўжэйшая за 12 хв, баллы вернуты». Замовіць тую ж песню, што ўжо ў чарзе, — «ужо ў чарзе, баллы вернуты». Пустую замову Twitch не дасць адправіць (поле абавязковае).
6. **✕ у доку.** Прыбраць замову гледача — у чаце «стрымер прыбраў «…» з чаргі, баллы вернуты», баллы вярнуліся.
7. **Змена лідара.** Замовіць песню і адразу закрыць док крыжыкам: замова з’яўляецца ў оверлэі адзін раз, паведамленне ў чаце — адно. Адкрыць док — замова адна. Тое ж з перазагрузкай оверлея, у якім працуе бот («Обновить кэш текущей страницы»).
8. **Spotify адключаны.** «Налады» → Spotify → «Адключыць»: праз ~5 с у доку «Узнагарода … на паўзе», на Twitch узнагарода на паўзе (купіць нельга). Падключыць Spotify — праз некалькі секунд зноў працуе.
9. **OBS зачынены.** Выйсці з OBS (*Файл → Выход*) і праз хвіліну паглядзець на ўзнагароду на старонцы канала: чакаецца «на паўзе». Калі не на паўзе — купіць яе, запусціць OBS: свежая замова трапляе ў чаргу (паведаміць Claude, што ўзнагарода не стала на паўзу).
10. **«Праверка» → Twitch:** «Злучэнне для замоў працуе», час апошняй замовы, «Чакаюць адпраўкі ў Twitch: 0».
11. **Адключыць Twitch.** «Налады» → Twitch → «Адключыць»: узнагарода на паўзе, док прапануе падключыцца зноў.

Вынікі: што спрацавала і што не; скрыншоты дока і чата пры праблемах. Пасля праверкі — вярнуць цану ў «Правілах замоў».

## Бот без сервера: старонкі з інтэрнэту (Этап 5, ADR-019)

Пасля гэтага `npm run dev` больш не патрэбны: OBS загружае док і оверлэй з `https://mashninski.github.io/spotify-bot-app/`.

### 1. Стварыць рэпазіторый для зборкі (адзін раз)
1. github.com → **+** уверсе справа → **New repository**.
2. **Repository name**: `spotify-bot-app`. **Public**. Нічога не дадаваць (без README, .gitignore, license) → **Create repository**.
3. Напісаць Claude «рэпазіторый гатовы» — Claude выкладзе зборку ў галіну `gh-pages`.
4. Пасля гэтага: рэпазіторый → **Settings → Pages** → *Build and deployment* → **Source: Deploy from a branch** → **Branch: gh-pages**, папка **/ (root)** → **Save**. Праз 1–2 хв адрас `https://mashninski.github.io/spotify-bot-app/` адкрываецца ў браўзеры (спіс старонак).

### 2. Перавесці OBS на новы адрас
1. Spotify Dashboard → ваша прыкладанне → **Settings → Edit** → у **Redirect URIs** дадаць `https://mashninski.github.io/spotify-bot-app/callback.html` → **Add** → **Save** (стары адрас можна пакінуць).
2. OBS → **Док-панели → Пользовательские док-панели браузера…** → у радку «Spotify-бот» замяніць URL на `https://mashninski.github.io/spotify-bot-app/dock.html` → **Применить**.
3. Крыніца оверлэя → **Свойства** → URL `https://mashninski.github.io/spotify-bot-app/overlay.html` → **ОК** (у кожнай сцэне, дзе ён ёсць; калі крыніца адна і тая ж — адзін раз).
4. У доку — нанова (новы адрас = новыя налады, адзін раз): «Налады» → пароль OBS → «Падключыцца»; Spotify — Client ID → «Падключыць Spotify»; Twitch — Client ID → «Падключыць Twitch»; «Правілы замоў», «Крыніца гуку». Узнагароду бот знойдзе сам.
5. **Галоўная праверка:** «Стан» → OBS → «obs-websocket» паказвае версію, а хваля ў оверлэі рухаецца. Калі obs-websocket не падключаецца — паведаміць Claude (браўзер OBS можа не пускаць старонку з інтэрнэту да `127.0.0.1`).
6. Закрыць тэрмінал з `npm run dev`, перазапусціць OBS — усё загружаецца само.
