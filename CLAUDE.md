# CLAUDE.md — правила работы Claude Code в проекте spotify-bot

Этот файл Claude Code читает в начале каждой сессии. Он объясняет **порядок работы** и указывает, где лежит актуальный контекст. Историю разработки здесь не дублируем — она в `docs/`.

## 0. Самостоятельность (ADR-005)

Автор дал добро: **в разработке Claude Code действует сам** и работает столько, сколько нужно для задачи, не спрашивая разрешения на каждый шаг. Сам выбирает решения, пишет и переделывает код, ставит зависимости, запускает проверки, делает commit, push и слияние своих веток в `main`. Решения записывает в документы и коротко сообщает автору, что сделано.

**Спрашивать автора обязательно**, только если дело касается:
- денег (платные сервисы, подписки, покупки, любые платежи);
- секретов (tokens, Client Secret, пароли, ключи) — их автор вводит сам в `.env`, Claude их не видит и не печатает;
- действий от имени автора во внешних аккаунтах (Twitch, GitHub-настройки, OBS у автора): регистрация приложений, публикация, сообщения, смена настроек;
- необратимых действий с историей и данными: `push --force`, `reset --hard`, переписывание истории, удаление веток или файлов вне проекта;
- смысла продукта: что должен уметь бот, как он ведёт себя для зрителей. Это определяет автор; техническую реализацию — Claude.

Вопрос не должен останавливать работу: задай его и продолжай всё, что от ответа не зависит.

## 1. Языки

- **Общение с автором — по-русски**: коротко, понятно, без воды. Автор — новичок в разработке: объясняй, что делаешь и зачем. Подробно объясняй по запросу, но о важных рисках и неочевидных обстоятельствах сообщай сам.
- **Всё, что попадает в проект, — по-белорусски**: документация в `docs/`, комментарии в коде, сообщения коммитов, описания веток/PR/issue, README, тексты логов для разработчика, тексты самого приложения (если автор не решил иначе).
- Технические термины остаются английскими (commit, branch, token, webhook, API, scope и т. д.). Имена переменных, функций и файлов — английские.
- Тексты для зрителей стрима (ответы бота в чате и т. п.): язык определяет автор. Пока не определён — спроси и запиши в `docs/DECISIONS.md`.
- Любой английский текст, который автор должен понять (вопросы, промпты), сопровождай русским переводом.
- Этот файл и инструкция чата (`docs/CLAUDE_PROJECT_INSTRUCTIONS.md`) написаны по-русски намеренно: это правила общения с автором, а не документация проекта (решение ADR-001).

## 2. Карта документов

| Файл | Что в нём | Когда обновлять |
|---|---|---|
| `docs/PROJECT.md` | Память проекта: цель, стек, актуальное состояние, открытые вопросы, **следующая задача** | При смене состояния, по окончании задачи |
| `docs/LOG.md` | Хронология: что сделано, изменено, удалено, переработано, проверено | После каждого логического шага |
| `docs/DECISIONS.md` | Технические и процессные решения с обоснованием | При каждом важном решении |
| `docs/BACKLOG.md` | Идеи, замечания, технический долг (на будущее) | Когда возникла идея, которую не делаем сейчас |
| `docs/SETUP.md` | Шаги автора по подготовке аккаунтов и инструментов | Когда появилось новое подготовительное действие |
| `docs/CLAUDE_PROJECT_INSTRUCTIONS.md` | Текст инструкции для Claude Project (обычные чаты) | Когда меняются правила работы (вместе с этим файлом) |
| `docs/CONTEXT.md` | Сгенерированный снимок контекста для чатов без доступа к репозиторию (в git не попадает) | По запросу и в конце крупного этапа |

Правила в `CLAUDE.md` и `docs/CLAUDE_PROJECT_INSTRUCTIONS.md` должны оставаться согласованными: меняешь один — проверь другой.

## 3. Старт каждой сессии (обязательно, без вопросов автору)

1. Прочитай `docs/PROJECT.md` (состояние и следующая задача) и `docs/DECISIONS.md`.
2. Прочитай только конец `docs/LOG.md` (последние ~40 строк) и нужные разделы `docs/BACKLOG.md`. Остальное — по необходимости, чтобы экономить контекст.
3. Выполни `git status` и `git log -10 --oneline`. Сравни с `PROJECT.md` и `LOG.md`: незавершённые изменения или расхождения — сообщи автору.
4. Определи задачу и критерии готовности. Если задачу дал автор в промпте — она главная; если нет — бери «Следующую задачу» из `PROJECT.md`.
5. Не хватает существенных данных — спроси автора, но **независимую работу продолжай**.
6. Автору документы не пересказывай. Скажи 2–3 строки: где мы, что делаю, что проверю.

## 4. Во время работы: что куда записывать

Записывай **сразу после логического шага**, а не в конце сессии.

- Что-то сделал или изменил → запись в `docs/LOG.md`.
- Что-то удалил или переработал → запись в `docs/LOG.md` с тремя полями: **причина**, **замена**, **как восстановить** (хэш коммита или тег; например, `git show <hash>:путь/к/файлу`). Перед удалением крупного куска кода сделай коммит или тег, чтобы восстановление было возможным.
- Принято важное решение (стек, библиотека, архитектура, правило работы) → `docs/DECISIONS.md`: контекст, решение, причины, альтернативы.
- Возникла идея, замечание или долг вне текущей задачи → `docs/BACKLOG.md`. **Не переключайся на неё.** Скажи автору одной строкой, что записано.
- Изменилось состояние проекта, список открытых вопросов или следующая задача → `docs/PROJECT.md`.
- Не пиши «задокументировано», пока изменения не записаны в файлы.
- Не создавай новых журналов и файлов-«заметок» без решения в `DECISIONS.md`. Система должна оставаться компактной.
- Записи в документах — на белорусском (см. раздел 1).

## 5. Git

- Коммиты маленькие, **на белорусском**, в форме `тип: краткое описание`. Типы: `дадаць`, `выправіць`, `перарабіць`, `выдаліць`, `дакументацыя`, `службовае`.
- Для крупной задачи — отдельная ветка `feature/<название-латиницей>`. Когда задача готова и проверена, Claude сам сливает её в `main` (ADR-005) и сообщает автору.
- `push` в `origin` (приватный репозиторий автора) Claude делает сам, без отдельного вопроса (ADR-005).
- Не делай `push --force`, `reset --hard`, не переписывай историю и не удаляй ветки без отдельного согласия автора с объяснением причины.

## 6. Секреты и безопасность

- Никогда не записывай tokens, Client Secret, пароли, ключи в код, документы, `LOG.md`, сообщения коммитов и вывод в чат.
- Секреты живут только в `.env` (он в `.gitignore`). В репозитории — только `.env.example` с названиями переменных без значений.
- Не печатай содержимое `.env`. Если секрет попал в чат, файл или коммит — остановись, сообщи автору и объясни, как его перевыпустить (rotate).

## 7. Проверка и честность статусов

Всегда различай **запланировано**, **сделано**, **проверено**. Не говори «готово», пока не проверено. Пиши, что именно и как проверено, а что проверить не удалось. Не утверждай, что что-то работает с OBS или Twitch, если ты это не запускал (или не можешь запустить) — в таком случае дай автору шаги для проверки.

## 8. Контекст и переходы между сессиями

- **Зачем переходы:** экономия токенов. Каждое сообщение в длинном чате заново «оплачивает» всю накопленную историю, поэтому большой чат дорог и хуже держит фокус. Новая сессия стартует с компактных документов из `docs/` и стоит намного дешевле.
- **Решает Claude.** Автор не следит за размером чата — Claude сам замечает, что чат разросся и зря тратит токены, и сам предлагает переход с готовым промптом.
- Одна крупная задача, самостоятельная функциональность или большой этап — одна сессия Claude Code. Не веди всю разработку в одном бесконечном чате.
- Мелкие задачи можно продолжать в той же сессии. Не предлагай новую сессию после каждой мелочи.
- Предлагай переход, когда завершён крупный этап, готова отдельная функциональность или контекст сильно вырос (много прочитанных файлов, длинный вывод команд, долгая переписка). Удобный момент — граница логического шага, а не середина правки. Не называй точный остаток контекста, если ты его не видишь.
- Перед переходом: (1) обнови документы; (2) зафиксируй сделанное, незавершённое и блокеры в `LOG.md` и `PROJECT.md`; (3) определи одну конкретную следующую задачу; (4) подготовь промпт.
- **Промпт целиком выдавай в ответе автору** (по-русски), последним блоком. Запись в файл или ссылка его не заменяют. В промпте: среда (Claude Code / обычный чат Claude), нужный доступ, что прочитать, задача, критерии готовности, проверки.
- Сам новую сессию или чат не открывай: автор открывает её и вставляет промпт. Не пиши «перейти в агентный режим» — называй конкретную среду.
- Для чата без доступа к репозиторию обнови `docs/CONTEXT.md` (см. ниже) и объясни автору, как его загрузить.

### Как создавать `docs/CONTEXT.md`

По запросу автора или в конце крупного этапа. Структура: заголовок с датой и хэшем последнего коммита (или «git нет»), затем полный `PROJECT.md`, список решений из `DECISIONS.md` (ID, название, статус, краткий вывод), последние ~15 записей `LOG.md`, открытые пункты `BACKLOG.md`. Без секретов. В конце скажи автору: «Замени файл `CONTEXT.md` в знаниях Claude Project (шаги в `docs/SETUP.md`)».

Не обещай автоматическую синхронизацию между чатом Claude и Claude Code: её нет, пока она не настроена и не проверена.

## 9. Отчёт в конце каждой сессии или этапа (по-русски, 4 пункта)

1. **Что сделано** — коротко и конкретно, с существенными проверками и ограничениями. Незавершённое не выдавай за завершённое.
2. **Один следующий шаг** — что именно нужно сделать автору. Если нужны его действия — полная пошаговая инструкция. Если нужна новая сессия — среда и готовый промпт.
3. **Что должно получиться** — какой результат ожидается и как его распознать.
4. **Где продолжаем** — остаться здесь или перейти; если перейти, то точно куда (Claude Code / обычный чат Claude / Claude с конкретными подключениями). Промпт для перехода — последний блок сообщения.

## 10. Общий контекст проекта

- Проект: `spotify-bot`. Новый этап — функциональность для OBS и стримов на Twitch. Состояние, стек и план — в `docs/PROJECT.md`.
- Настройки и tokens пользователя приложение хранит в своём файле настроек в профиле пользователя, а не в коде и не в `.env` (ADR-006). `.env` — только для разработки.
